# 技术设计

## 已知事实与约束

- 现有 Dify 跨境电商客服工作流已完成本地验收，支持英语、越南语、泰语、商品/物流/售后问答和人工转接。
- 用户选择前后端独立项目：Vue 3 前端、Node.js + TypeScript + Fastify 后端。
- 后端需使用 MySQL 持久化会话与人工状态，并接入飞书 Webhook 和飞书自建应用机器人。
- Dify API Key、飞书令牌、数据库凭据不得进入浏览器包或前端运行时公开配置。
- 首期不接入电商平台，不执行真实退款/赔付，不做数据分析和可视化主题编辑器。

## 目标与非目标

### 目标

- 为消费者和客服提供两种适配不同场景的界面。
- 以稳定的后端 API 隔离 Dify 和飞书的凭据、协议与错误。
- 让会话、摘要和人工转接状态可恢复、可追踪、可同步。
- 让视觉定制不侵入业务组件，并能在本地和云环境部署。

### 非目标

- 不重写 Dify 工作流内部逻辑。
- 不实现交易执行、外部平台订单查询或完整客服工单系统。
- 不在首期建设主题编辑器、数据分析和复杂权限管理后台。

## Decisions

### 决策：前后端独立项目

- **选择**：独立 Vue 3 前端项目 + 独立 Fastify API 项目。
- **理由**：明确浏览器、业务服务、Dify 和飞书之间的信任边界，便于分别部署和扩展。
- **替代方案**：纯前端直连 Dify 部署最快，但会暴露 API Key；同仓全栈应用耦合更高，不利于未来替换渠道。
- **后果**：需要处理跨域、环境变量、版本协同和两套部署流水线。

### 决策：Fastify 作为 API 适配层

- **选择**：Node.js + TypeScript + Fastify，按 Dify、会话、飞书、健康检查划分模块。
- **理由**：轻量、适合 SSE 流式转发，且足以承载会话持久化和飞书 Webhook。
- **替代方案**：NestJS 结构更重但样板更多；纯 Serverless 简化部署但不利于长连接、事件幂等和后续人工协作。
- **后果**：需要自行约束模块边界、错误模型和鉴权中间件。

### 决策：后端持久化到 MySQL

- **选择**：保存会话、消息、Dify conversation ID、摘要、语言、人工状态、转接事件和飞书事件去重键。
- **理由**：支持历史恢复、双模式共享状态、飞书回写和后续查询；MySQL 与用户选择一致。
- **替代方案**：SQLite 适合单机试验但不适合多客服；只保存浏览器状态无法支持客服工作台和飞书协作。
- **后果**：需要迁移、连接池、备份和生产部署配置。

### 决策：飞书双通道

- **选择**：Webhook 用于快速通知，自建应用机器人用于验签、接收客服指令和回写状态。
- **理由**：同时覆盖低延迟提醒和双向协作；任一通道故障时，主会话仍保留在系统中。
- **替代方案**：只用 Webhook 只能通知不能接管；只用自建应用需要更完整的事件订阅和权限配置。
- **后果**：需要维护签名/令牌、事件幂等、重试和飞书权限说明。

### 决策：配置化主题

- **选择**：主题配置文件映射为 CSS 变量，两种页面共用设计令牌。
- **理由**：满足页面风格可定制，同时控制首期范围和运行时复杂度。
- **替代方案**：硬编码风格不可复用；可视化编辑器会引入持久化、权限和预览状态管理。
- **后果**：需要定义配置 schema、默认值和非法值回退规则。

## 关键边界

```text
消费者/客服浏览器
        │ HTTPS + 自有会话 API
        ▼
独立 Fastify 服务 ── MySQL
        ├── Dify Adapter ── Dify Workflow API
        └── Feishu Adapter ── Webhook + 自建应用机器人
```

前端只认识自有 API；Dify 和飞书协议、密钥、重试和错误映射均封装在后端。

## 风险与验证

- **Dify SSE 事件格式变化** → 以适配器封装事件解析，并保留原始事件关联日志 → 使用流式、结束、错误和中断样例验证。
- **飞书重复或伪造事件** → 验签、时间窗口、事件去重键和幂等更新 → 重放、过期签名和无权限指令测试。
- **会话状态不一致** → MySQL 事务、版本号和事件状态机 → 并发回复、重复回调和刷新恢复测试。
- **密钥泄露** → 后端环境变量/密钥管理、前端构建产物扫描 → 检查浏览器网络、构建包和日志。
- **两种页面行为漂移** → 共享 API client、领域类型和状态映射 → 对同一会话执行双模式一致性验收。
- **部署配置不完整** → 启动前环境变量校验和健康检查 → 缺密钥、数据库不可用、Dify 不可用场景验证。
